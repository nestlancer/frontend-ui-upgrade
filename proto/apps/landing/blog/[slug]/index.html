Cutting Deploy Time from 45 Minutes to Five

NE
Nestlancer Editorial
8 min read · Engineering practice
DEPLOY PIPELINE · BEFORE/AFTER

A 45-minute deploy is not a tooling problem — it is a feedback problem. When a deploy takes three quarters of an hour, nobody ships on Friday, nobody ships after lunch, and "continuous" becomes a slogan. Here is how we took a client's NestJS monolith from 45 minutes to five, in order of what actually mattered.

1. Profile before you optimize

The pipeline spent 19 minutes in dependency install, 14 minutes compiling TypeScript, 8 minutes building a Docker image containing the world, and 4 minutes on rollout. Optimizing rollout first would have saved nothing that matters.

2. Cache like the build depends on it

# .github/workflows/deploy.yml — the two lines that saved 19 minutes
- uses: actions/setup-node@v4
  with: { cache: pnpm, cache-dependency-path: pnpm-lock.yaml }
- run: pnpm fetch # warm store from lockfile, offline install after

Lockfile-keyed pnpm store caching took install from 19 minutes to 90 seconds. The trick is separating fetch (network, cacheable) from install (local, deterministic).

3. Split build from bundle

  • TypeScript compiles in CI once; the Docker stage copies dist/ instead of recompiling.
  • Production image went from 1.9 GB to 240 MB (node:22-alpine + pnpm deploy --prod).
  • Layer caching keyed on lockfile hash: source-only changes rebuild in ~40s.
Ten engineers regained roughly eleven hours of waiting — every single week.

4. Make rollback boring

Five-minute deploys only stay safe when rollback is faster than panic. We pinned every release to an immutable image digest, kept the previous task definition warm, and wired a one-command rollback into the runbook. Friday deploys came back.

Results after six weeks

  • Median deploy: 4m 40s (p95: 6m 10s)
  • Deploys per week: 9 → 34
  • Change-failure rate: down 31% (smaller diffs, more often)

Speed is a feature of culture as much as tooling: once deploys are cheap, review becomes the bottleneck — which is exactly where a senior team should spend its minutes.
